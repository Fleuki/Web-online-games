# Игры на двоих

Сервер и клиент для онлайн-игр вдвоём: один создаёт комнату, кидает ссылку
другу, играют из разных мест.

Не «два игрока за одним экраном», а настоящий онлайн: **сервер — единственный
источник правды**, клиент только рисует состояние и шлёт намерения.

- **Сервер:** Node.js + Colyseus + TypeScript
- **Клиент:** HTML/CSS/JS без фреймворков и сборки
- **База:** нет. Комнаты живут в памяти процесса
- **Регистрация:** нет. Ник хранится в `localStorage`

## Запуск

```bash
npm install
cp .env.example .env
npm run dev
```

Откройте `http://localhost:2567`. Чтобы проверить игру вдвоём, откройте вторую
вкладку **в приватном окне** или в другом браузере: обычная вторая вкладка
делит `localStorage` и `sessionStorage` с первой.

### Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер в режиме разработки, перезапуск при правках |
| `npm run build` | Компиляция TypeScript в `build/` |
| `npm start` | Запуск собранного сервера (сначала `npm run build`) |
| `npm test` | Тесты игровых модулей |
| `npm run typecheck` | Проверка типов без сборки |
| `npm run clean` | Удалить `build/` |

### Настройки

Все — в `.env`, образец в `.env.example`:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PORT` | `2567` | Порт HTTP и WebSocket |
| `HOST` | `0.0.0.0` | Адрес прослушивания |
| `DEFAULT_GAME` | `treegame` | Игра в новых комнатах |
| `RECONNECT_TIMEOUT` | `60` | Секунд ожидания игрока после обрыва |

### Проверить с телефона

Сервер уже слушает `0.0.0.0`. Узнайте адрес компьютера в локальной сети
(`ip addr` / `ipconfig`) и откройте `http://192.168.x.x:2567` на телефоне.

Кнопка «Скопировать ссылку» использует `navigator.clipboard` — он работает
только на `https://` и на `localhost`. По локальному IP по `http://` сработает
запасной путь через `document.execCommand("copy")`.

## Как игра подключается к ядру

`GameRoom` не знает ни про дерево, ни про шахматы. Он берёт модуль из реестра
и вызывает пять вещей:

```ts
meta                                     // { id, name, minPlayers, maxPlayers, icon }
createState(players)                     // начальное состояние
validateAction(state, playerId, action)  // true / false
applyAction(state, playerId, action)     // новое состояние
checkGameOver(state)                     // null | { winnerId, reason }
```

Добавление игры — новая папка в `server/games/` и одна строка в
`registry.ts`. Ноль правок в ядре.

Состояние партии уезжает клиенту в поле `gameState` как JSON. Так ядро
остаётся независимым от формы состояния конкретной игры; платим за это тем,
что состояние летит целиком, без дельт. Для «счёт: 7» цена нулевая — игра,
которой это станет дорого, заведёт собственную `Schema`.

### Клиентская часть игры

Зеркальный контракт в `client/js/games/`:

```js
window.Games.register({
  id: "treegame",
  mount: function (root, api) { /* один раз строит разметку */ },
  render: function (state, api) { /* рисует состояние */ }
});
```

`api` = `{ root, myId, players, isFinished, winnerId, send(action) }`.
Экран комнаты не знает, что рисует модуль: DOM, канвас или что угодно.
Свои стили модуль приносит с собой, в общий `style.css` лезть не нужно.

### treegame

Оба игрока рубят одинаковый ствол наперегонки — у каждого своя позиция на нём.

- **Ветки** растут слева или справа. Удар с той стороны, где ветка, не даёт
  очка и отнимает управление на `stunDurationMs`. Смерти нет: переждал и рубишь
  дальше.
- **Побеждает** тот, кто первым нарубит `targetScore`.
- **Действие:** `{ type: "chop", side: "left" | "right" }`.
- **Управление:** тап по левой или правой половине экрана, на десктопе —
  стрелки влево/вправо (и `A` / `D`).

Настройки — в `server/games/treegame/config.ts`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `targetScore` | `20` | Счёт, на котором партия заканчивается |
| `stunDurationMs` | `1000` | Длительность оглушения |
| `chunkSize` | `50` | Размер порции генерации ствола |
| `safeStart` | `5` | Сегментов без веток в начале |
| `maxSameRun` | `3` | Максимум веток подряд с одной стороны |
| `branchChance` | `0.6` | Доля сегментов с веткой |
| `lookahead` | `10` | За сколько сегментов до конца догенерировать |

#### Ствол

Ствол детерминирован: сид рождается на сервере при старте партии, входит в
состояние и уезжает обоим игрокам — картинка у них совпадает до сегмента.
Генератор — mulberry32, `Math.random()` тут не годится.

Ствол растёт порциями по 50 сегментов: когда игрок подходит к концу
сгенерированного участка, догенерируется следующая. Участок считается от
нулевого сегмента целиком, поэтому продолжение, посчитанное позже, совпадает
с тем, что получилось бы при генерации всего ствола сразу.

Срубленное низовье из состояния выбрасывается — у каждого сегмента есть
абсолютный `index`, так что нумерация не сбивается. Без этого в каждое
обновление состояния попадал бы весь пройденный ствол.

#### Предсказание на клиенте

Клиент проигрывает анимацию удара сразу, не дожидаясь ответа сервера: он
знает и ствол, и правило, поэтому считает исход сам. Расхождения принимает
как истину — сервер главнее. Если сервер ушёл вперёд, клиент подтягивается
немедленно; откатывать предсказание он начинает, только когда новых ударов
не было полсекунды, иначе при частых тапах счёт дёргался бы.

Оглушение клиент отсчитывает по своим часам с момента, когда узнал о нём:
`stunnedUntil` — время сервера, а часы на телефоне могут врать.

## Что уже работает

1. Игрок вводит ник в лобби (сохраняется в `localStorage`) и создаёт комнату
2. Сервер выдаёт код из 4 символов
3. Игрок попадает на `/r/КОД`, видит код и кнопку «Скопировать ссылку»
4. Второй открывает ссылку, вводит ник, попадает в ту же комнату
5. Оба видят список игроков в реальном времени
6. Когда игроков двое — хост нажимает «Начать»
7. Оба рубят свой ствол наперегонки, счёт и оглушения считает сервер
8. Кто первым дошёл до цели — победил, результат видят оба

Есть и вход по коду руками — на случай, когда ссылку неудобно переслать.

### HTTP API

| Метод | Путь | Ответ |
|---|---|---|
| `POST` | `/api/rooms` | `{ "code": "ABCD" }` — создаёт комнату. Необязательное тело `{ "gameId": "..." }` |
| `GET` | `/api/games` | `{ "games": [...], "defaultGame": "treegame" }` — реестр игр |
| `GET` | `/r/КОД` | Экран комнаты |

Всё остальное общение идёт по WebSocket через Colyseus.

### Код комнаты

4 символа из алфавита `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` — 32 символа,
около миллиона комбинаций. Похожие пары выброшены целиком: нет ни `0`, ни `O`,
ни `1`, ни `I`, поэтому при переписывании кода с чужого экрана перепутать
нечего.

Комнату создаёт сервер по запросу из лобби (`POST /api/rooms`) и сразу отдаёт
код. Если по ссылке за 5 минут никто не пришёл, пустая комната закрывается.

## Реконнект

Разработка идёт с телефона: экран гаснет, сеть моргает, приложение
сворачивается. Если игра при этом умирает — продукт мёртв. Поэтому:

- при обрыве игрок **не удаляется** — сервер держит его место через
  `allowReconnection` 60 секунд (`RECONNECT_TIMEOUT`);
- клиент показывает «Переподключение...» и сам пытается вернуться, пока идут
  эти 60 секунд;
- соперник видит «*Имя* потерял связь. Ждём N секунд...» с обратным отсчётом;
- вернулся — партия продолжается с того же места, счёт цел;
- не вернулся — засчитывается поражение, победа достаётся оставшемуся;
- осознанный выход (кнопка «Выйти») ждать не заставляет — это сдача.

Перезагрузка страницы посреди партии тоже переживается: токен реконнекта
лежит в `sessionStorage`, после F5 игрок возвращается в ту же партию.

Секунды в отсчёте клиент считает у себя, от момента, когда увидел обрыв:
серверное время сюда не передаётся, а часы на телефоне могут врать.

## Мобильные требования

- `viewport` без масштабирования, `viewport-fit=cover`
- `touch-action: manipulation`, отключены контекстное меню, выделение текста и
  жесты масштабирования (в полях ввода всё это оставлено)
- вёрстка от 360px, кнопки не мельче 48px
- размер шрифта в полях ввода 16px, иначе iOS зумит страницу при фокусе

## Версии Colyseus

Сервер и клиент намеренно закреплены на линии 0.16:

- `@colyseus/core` **0.16.24** (не `^`) — в 0.16.25 сломана публикация:
  зависимость `@colyseus/greeting-banner` уехала как `workspace:^`, и `npm`
  такую установить не может;
- сервер 0.17 требует `@colyseus/schema` 4, а свежий браузерный клиент
  `colyseus.js` 0.16.x — `@colyseus/schema` 3. Пара несовместима по формату
  состояния, поэтому берём согласованную 0.16.

`npm audit` показывает предупреждения в транзитивных зависимостях этой линии
(`nanoid` 3 внутри `@colyseus/core`). Закрываются они переходом на 0.17,
то есть ценой рабочего клиента, — так что ждём клиент под 0.17.

Клиентская библиотека отдаётся своей копией из `node_modules` по
`/vendor/colyseus.js` — без CDN.
